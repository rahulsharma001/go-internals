# Engineering Study Plan

## Operating rule

Reading is preparation input, not readiness evidence. For each active topic: learn → explain → cold code/design → test failure paths → modify under a timer → record mistakes → re-test.

## Current order

1. Follow [[Current Week]] and the Level 1 sequence in [[Go Learning Path]].
2. Build DSA attempts from [[DSA Map of Content]]; no attempt corpus exists yet.
3. Add bounded concurrency only after foundation code is executable.
4. Practice [[System Design Interview Framework]] with one success and one failure flow.
5. Verify behavioural/project claims before using them as evidence.

## Daily loop

- 15 minutes: active recall from [[Quick Revision Index]].
- 45–60 minutes: one hidden-solution drill or DSA attempt.
- 15 minutes: requirement modification and explanation.
- 10 minutes: record an observed mistake and schedule a re-test, if a real failure occurred.

## Weekly proof

- At least one timed coding session with correctness, complexity, communication, and modification recorded.
- At least one system-design outline using the full framework.
- Overdue re-tests resolved before expanding advanced internals.
- At most three outcomes in [[Current Week]].

## Readiness gates

Use [[Google Engineering Roadmap]] for language fluency, general coding, system design, behavioural/leadership evidence, mocks, repeated mistakes, and applications. A topic is not interview-ready until explain, implement, modify, production reasoning, and recent re-test evidence exist.
