# System Design Practice Tracker

This table records **performed work**, not note availability. Enter a score only after preserving the attempt or mock feedback. A canonical reference being complete does not change readiness.

## Status rules

- `not-started`: no reconstruction evidence.
- `understanding`: first read/prediction pass recorded.
- `reconstruction-needed`: blank-page attempt exposed structural gaps.
- `mock-needed`: untimed reconstruction is sound; no scored 45-minute mock.
- `follow-up-needed`: mock baseline is acceptable but deep-dive/adversarial handling is weak.
- `interview-ready`: at least two recent 80+ mocks, no rubric dimension below 70%, a follow-up round, and completed 1/3/7/14-day re-tests.

Allowed statuses are exactly: `not-started`, `understanding`, `reconstruction-needed`, `mock-needed`, `follow-up-needed`, `interview-ready`.

## Update protocol

1. Link or name the dated attempt in the reconstruction/mock cell; do not merely replace `☐` with a claim.
2. Copy the eight category scores from [[System Design Mock Rubric]].
3. Add only an observed recurring error to the mistake column and to [[Common Mistakes and Re-test Queue]].
4. Set the next review for 1, 3, 7, or 14 days based on the current lifecycle stage.
5. Change readiness by the rules above, not confidence or note-completion.
